User Input, Trust, & Injections:
- A line in a login form that trusts user input is known as a field, this takes in information like your email, username, password, etc.
- These types of forms are built off of the trust of the user to input those bits of information, but they should not as a default. Other bits of information that can bypass the form and its guardrails are called SQL injections, where lines of SQL code can used an input and override the form's original purpose for a hacker's own malicious purposes.
- NEVER TRUST USER INPUT! Always have some sort of guardrail to prevent these situations from happening.
- With SQL injections, the database receives a query that bypasses authentication. Passing things like the username seperately as a parameter can work as a defender. Always retrieve password hashes by username, verify the password against it, and don't store them in plain-text.

Phishing vs Legit (with AI-assisted examples):
- Emails such as benefits@northstar.ex compared to benefits-team@northstar.ex can make or break an email due to the legitimacy provided by the company. Always contact the actual company whenever there is suspicion about certain information.
- Subject headers: Headers in phishing emails may have a tone of urgency in them in order to make it seem like there is an emergency or time-limited situation (i.e. "You have 2 hours to verify or your delivery is canceled.").
- Email content: The content of the emails, especially for phishing emails, can include things like asking for login or account credentials, unfamiliar links, urgency, and secrecy between the users (i.e. "Can this only be between us before I announce it?", "Please enter your account information in this form immediately", "Complete this form to win $10K with this link!").
- TIP: Always double check through a separate channel, like the actual company itself.
